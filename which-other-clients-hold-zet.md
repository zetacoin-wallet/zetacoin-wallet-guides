Zetacoin Wallet is the official desktop client and the only wallet that runs a full node for ZET. Other wallets can hold ZET without the node: Komodo Wallet, the CoinMunity mobile wallet and Gemmer are named by the project. Hardware wallets do not support ZET natively, so the desktop client remains the reference.

## The official client

Zetacoin Wallet is a Qt desktop application for Windows, macOS and Linux. It holds keys in `wallet.dat`, syncs the full chain and supports sending, receiving, staking and mining through a local node.

The advantage is verification: balances come from blocks your machine checked rather than from a server. The cost is setup time and about 1 GB of disk for the chain.

For anyone holding a meaningful balance, this is the wallet to use, because it is the one whose behaviour the rest of this documentation describes.

The full walk-through, with the checks in order, is in [What the Zetacoin Desktop Client Does](https://github.com/zetacoin-wallet/zetacoin-wallet-guides/blob/main/what-the-desktop-client-does.md).

## Wallets that hold ZET without the node

Third-party wallets trade verification for convenience. They hold keys or use a service to read balances, which makes them lighter and quicker to set up.

| Wallet | Type | Node | Notes |
| --- | --- | --- | --- |
| Zetacoin Wallet | desktop | yes, full node | official client, staking and mining |
| Komodo Wallet | desktop and mobile | no | multi-coin, self-custody |
| CoinMunity | mobile | no | mobile-first, named by the project |
| Gemmer | desktop | no | named by the project |

A wallet that does not run a node depends on someone else's node for balances. That is acceptable for small amounts and inconvenient when a service is down or a coin is dropped from its list.

## Hardware wallets and ZET

Hardware wallets support a fixed list of coins, and ZET is not on the lists of the major devices. There is no native integration, which means keys cannot be kept on a hardware device and used with the desktop client.

That is a real limitation for anyone used to signing on a hardware device. The compensating practice is discipline: encrypt the wallet, keep the file off the machine, and never type the passphrase into anything but the client.

For the background behind this step, [Does Zetacoin Use a Seed Phrase?](https://github.com/zetacoin-wallet/zetacoin-wallet-guides/blob/main/is-there-a-seed-phrase.md) covers the same ground in more detail.

## Choosing between them

Use the desktop client if you stake, mine, run a node or hold a large balance. Use a lighter wallet if you want a mobile view or a small spending balance, and accept that it depends on someone else's infrastructure.

Do not split a staking balance across several wallets expecting better results. Selection is weighted by stake, so splitting reduces the chance per wallet without changing the total.

## Moving between wallets

Moving funds between wallets is an ordinary send: copy a receiving address from the destination wallet, confirm it begins with `9`, and send from the source.

Keep the source wallet intact until the destination shows the balance, and back up the destination wallet's file once funds arrive. A move that ends with funds in an unbacked wallet has not improved anything.

## What no wallet can do

No wallet can recover a forgotten passphrase, reverse a transaction or restore coins from a seed phrase that does not exist. Those limits come from the design, not from the choice of software.

Third-party wallets add their own limits: a service can delist a coin, and a mobile wallet can lose access to a node. Knowing which failure is yours and which is the provider's is part of choosing.

## Common questions

### Does Ledger or Trezor support ZET?

Not natively. There is no hardware wallet integration, so the desktop client remains the way to hold ZET with your own keys.

### Can I use a mobile wallet for ZET?

Yes, the CoinMunity wallet is named by the project for mobile use, without a local node.

### Is the desktop client required for staking?

It is the wallet that stakes, because staking needs a synced node with the keys present.

### Which wallet is safest?

The official client with an encrypted wallet file and an off-machine backup. Safety comes from the backup and the encryption more than from the brand.

## What "support" means for a wallet

A wallet supports a coin when it can hold its keys and construct valid transactions for its chain. That is a lower bar than running a node, and it is why a multi-coin wallet can hold ZET without knowing anything about hybrid consensus.

The difference shows up in the features. A wallet without a node cannot stake, cannot serve blocks, and cannot validate independently. It can hold and send, which is enough for a spending balance and not enough for the rest of what this coin does.

## The trade in practice

Lighter wallets are convenient and depend on infrastructure someone else runs. When that infrastructure changes, the wallet may stop showing a balance even though the coins are untouched on the chain.

The desktop client is heavier and depends only on the network. That is why it remains the recommendation for a balance you intend to keep, and why holders often use both: the client for storage and staking, a lighter wallet for small amounts on the move.

{{ARTICLE:zetacoin-wallet-seed-phrase-explained}} explains why the backup of the client is a file rather than words, which is the main operational difference from wallets that use phrases.

## How to move a balance safely between wallets

Send a small amount first, confirm it arrives, then move the rest. That sequence proves the destination wallet's address format, its ability to see the chain, and your own access to it.

Then back up the destination before the main transfer, not after. A wallet that receives a balance before it has a backup is gambling on the next hour, and the gamble has no upside.

Finally, keep the source wallet intact until the destination shows the full amount. Deleting the old wallet as soon as the transaction is broadcast removes the fallback you would need if the destination turns out to be wrong.
