Zetacoin Wallet is safe to use when it comes from the project's own release page and is kept on the current release. It is open source, holds keys locally in `wallet.dat`, encrypts with AES-256-CBC and never asks for a seed phrase. The main risks are an unencrypted file, an unsaved backup and installing a copy from somewhere else.

## What "safe" can and cannot mean

No wallet is safe in the absolute sense, and any page claiming otherwise is selling something. What can be assessed is concrete: where the keys sit, who can reach the file, and what happens when the machine fails. What can be assessed is where the keys live, who can reach them, what happens when the machine fails, and whether the software is what it claims to be.

On those four questions this client answers well. Keys live on your machine, in a file you control, encrypted with a passphrase you choose, in software whose source is public. What it cannot protect you from is a lost disk, a forgotten passphrase or a download from a lookalike domain.

| Risk | Where it comes from | What removes it |
| --- | --- | --- |
| Lost coins after a disk failure | no backup of `wallet.dat` | an off-machine copy, refreshed after big transactions |
| Stolen file, readable | wallet not encrypted | encryption with a passphrase you store separately |
| Malware on the machine | anything with file access | a clean machine, no remote-access tools, no cracked software |
| Fake installer | a download from a lookalike site | install only from the project's release page |
| Forgotten passphrase | no recovery mechanism exists | a written record kept offline, never in a chat or a note app |
| Sending to the wrong chain | a `Z...` legacy address | check every address begins with `9` |

The full walk-through, with the checks in order, is in [What the Zetacoin Desktop Client Does](https://github.com/zetacoin-wallet/zetacoin-wallet-guides/blob/main/what-the-desktop-client-does.md).

## The design choices that protect you

The client runs a full node, so it verifies balances against blocks it checked rather than trusting a server. There is no account, no login and no custodian: nobody else holds a copy of your keys, and nobody can freeze the balance.

Encryption uses AES-256-CBC. A locked wallet cannot sign transactions, which means a stolen file is useless without the passphrase  -  as long as the file was encrypted before it was copied. An unencrypted `wallet.dat` is readable by anyone who has the file, which is the single most common self-inflicted risk.

There is no seed phrase. That sounds like a weakness and is actually a clarity: the file is the wallet, so the backup question has one answer instead of two. The trade is that a lost file with no copy cannot be rebuilt from words, because no words were ever generated.

## The design choice that does not protect you

Binaries are not signed with a commercial certificate, so Windows Defender and macOS Gatekeeper warn on first launch. The warning is about provenance, not behaviour, and it is the same warning a small open-source project gets regardless of what the code does.

That puts weight on how you obtained the file. Downloading from the project's release page and checking the published SHA-256 checksums turns the warning into a known quantity. Downloading from a search result, a forum attachment or a "mirror" does not, and no amount of caution afterwards repairs a bad installer.

This is also why lookalike domains matter more than the average user expects. {{ARTICLE:where-to-download-official-zetacoin-wallet}} exists to make that check mechanical, and {{ARTICLE:zetacoin-wallet-hack-risk}} covers the threat model in more detail.

There is a subtler point behind the warning. An installer that behaves correctly is not proof of a correct installer, because malicious software can behave correctly for weeks. The only practical defence is the hash: if the file matches what the project published, you are running the project's code, and every other reassurance is secondary.

For the background behind this step, [How to Back Up the Zetacoin Wallet](https://github.com/zetacoin-wallet/zetacoin-wallet-guides/blob/main/how-to-back-up-the-dat-file.md) covers the same ground in more detail.

## What you should do in the first ten minutes

1. Confirm the file came from the project's release page and matches the published checksum.
2. Open the client and let it sync, so you are not debugging two problems at once.
3. Encrypt the wallet with a passphrase, then verify the wallet locks and unlocks.
4. Copy `wallet.dat` to a second device or an offline drive.
5. Check that your receive address begins with `9`.

Those five steps take less time than reading this page, and they close the risks that account for nearly every reported loss: no backup, no encryption, wrong download. None of them require trusting the project, which is the point  -  they are checks you can run yourself.

{{ARTICLE:how-to-backup-zetacoin-wallet}} covers step four properly, and {{ARTICLE:zetacoin-wallet-encryption-passphrase}} covers step three, including what to do if you want to change the passphrase later.

## What the project can and cannot do for you

The project maintains the software, publishes releases and answers issues. It cannot move your coins, reverse a transaction, reset a passphrase or restore a lost file  -  the chain has no administrator and the wallet has no recovery mechanism.

That is worth stating because scams depend on the opposite belief. A message claiming to be support and asking for your wallet file, your passphrase or a "verification" transaction is a theft attempt, without exception. Legitimate support never needs any of those things, because it cannot use them even if it had them.

## Common questions

### Is Zetacoin Wallet open source?

Yes, the code is public and the releases are published with notes. The licence is a separate question covered in the audit and open-source page, where the project's own statement is used rather than an assumption.

### Can a Zetacoin wallet be hacked?

Only through your machine or your file: malware that reads an unencrypted `wallet.dat`, or a fake installer. The chain itself has no central server to compromise, and a properly encrypted file is not usable without the passphrase.

### Does the wallet have a seed phrase?

No. Keys live in `wallet.dat`, so that file is the backup. There are no words to write down and no restore-from-phrase flow.

### Is it safe to keep coins in the desktop wallet?

Yes, with encryption and an off-machine backup. It is safer than leaving them on an exchange you do not control, provided the backup exists and the file is encrypted.

## The checks that matter most

Install from {{RELEASE}}, encrypt before funding, back up before funding, and verify the `9` prefix on every address you use, every time. Those four habits cover the realistic risk surface of a self-custody wallet.
