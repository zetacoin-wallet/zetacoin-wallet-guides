Download Zetacoin Wallet for Windows from the project's GitHub releases page, using the 64-bit build for Windows 10 or 11. Run the installer, let the client sync, then back up `wallet.dat` before you fund it. The download is about 24 MB and the client needs roughly 2 GB of RAM and 1 GB of disk for chain data.

## Before you download anything

Check three things first, because a wrong download is the only mistake in this process that cannot be undone. Confirm you are on the project's own release page, confirm the file is the Windows build, and confirm the size is in the expected range rather than a few hundred kilobytes.

Search results for a coin's wallet are a bad neighbourhood. Lookalike domains copy the layout, list the same version numbers, and serve a file that behaves like a wallet while sending keys elsewhere. The project publishes checksums for its builds, so the safe path is: download, compare the hash, then install.

| Check | Expected |
| --- | --- |
| Source | the project's GitHub releases page |
| File type | Windows installer for the current release |
| Approximate size | about 24 MB |
| Platform | Windows 10 or 11, 64-bit |
| Checksum | matches the published value |

The full walk-through, with the checks in order, is in [Where the Official Zetacoin Wallet Lives](https://github.com/zetacoin-wallet/zetacoin-wallet-guides/blob/main/where-the-official-installer-lives.md).

## Install, step by step

1. Download the Windows build from {{RELEASE}} and note the file name.
2. Compare its SHA-256 value with the published checksum. If they differ, delete the file and download again.
3. Run the installer. Windows SmartScreen will warn that the publisher is unverified, because the binaries are not signed with a commercial certificate; choose the option to run it anyway only after step two.
4. Launch Zetacoin Wallet and let it create its data directory at `%AppData%/zetacoin/`.
5. Wait for the sync. A standard sync takes 30 minutes to two hours; the bootstrap archive brings it under 15 minutes.
6. Encrypt the wallet, then copy `wallet.dat` somewhere off the machine.

The order matters. Encrypting before funding and backing up before funding are what turn a working install into a safe one. A wallet with coins and no backup is one disk failure away from being a wallet with no coins, and the copy takes seconds to make.

## The SmartScreen warning, explained

Windows shows a warning for any executable it has not seen enough of, and an unsigned open-source wallet trips it every release. The warning says the publisher is unknown, which is accurate: there is no paid certificate attached to the binary.

It is not a virus report, and it is not specific to this project. It also does not mean the file is safe  -  it means Windows cannot tell you either way. That is precisely why the checksum step exists: the hash tells you whether the file is the one the project published, which is the only provenance signal available.

If you skip the hash and click through, you have made a trust decision without evidence. If you check the hash, the warning becomes a known cosmetic issue rather than an open question.

One more practical note about SmartScreen: the warning appears the first time the installer runs and again after each upgrade, because every release is a new binary with no reputation history. If you reinstall often, keep the hash page open while you do it, so the check is a habit rather than an afterthought.

For the background behind this step, [Zetacoin Wallet System Requirements](https://github.com/zetacoin-wallet/zetacoin-wallet-guides/blob/main/system-requirements-for-the-client.md) covers the same ground in more detail.

## Configuring the client on Windows

The configuration file is `zetacoin.conf` in `%AppData%/zetacoin/`. The setting most people need is `paytxfee=0.001`, the recommended fee; the network port is 17333 and the RPC port is 6332 if you plan to mine or script against the node.

Port forwarding is optional. Without it the wallet still syncs and stakes; with it, more peers can reach you and your node contributes more to the network. If you enable it, forward 17333 to the machine running the wallet.

Disk use grows with the chain. The current chain needs about 1 GB, and the folder also holds the wallet, the configuration and logs, so leave headroom rather than filling the drive.

## Common Windows problems and their fixes

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| "No block source available" | no reachable peers yet, or a firewall block | allow the client through the firewall, then restart |
| Sync stuck at a low percentage | old chain data in the data directory | move the folder aside and resync, or use the bootstrap |
| Wallet opens then closes | an incomplete install or a missing runtime | reinstall from the current release |
| Balance zero after restore | wallet not rescanned | rescan the chain from the console |
| Antivirus quarantines the installer | heuristic on unsigned binaries | verify the checksum, then allow the file |

The first two account for most reports, and both are local rather than network problems. {{ARTICLE:zetacoin-wallet-not-syncing-fix}} walks through them in order, and {{ARTICLE:fix-no-block-source-zetacoin-wallet}} handles the specific message.

## Upgrading over an older installation

The current client uses the same data directory as earlier versions, including the legacy wallet. Installing over an old installation can therefore put an old `wallet.dat` in the path of the new client, which is how people end up with a wallet that reads a retired chain.

Back up the old file first, move the old chain data to a separate folder, then install and let the current client build its own chain. Renaming the folder is reversible; overwriting it is not. {{ARTICLE:update-zetacoin-wallet-safely}} covers the sequence in full, and {{ARTICLE:move-zetacoin-wallet-new-computer}} covers moving to a new machine.

## Common questions

### Is there a 32-bit Windows build?

No. The supported platforms are Windows 10 and 11, 64-bit. Older 32-bit systems are not built for.

### Do I need to install anything else first?

No. The Windows build is self-contained; you do not need a separate runtime, and you do not need to compile anything.

### Why is the download only about 24 MB?

Because it is the client, not the chain. The blockchain is downloaded during the first sync and stored in the data directory, which is why disk use grows after installation.

### Can I run it from a USB drive?

The client expects a writable data directory and a stable path. Running from removable media works only if the whole folder travels with it and the drive letter does not change, which makes it a poor choice for a wallet you rely on.
