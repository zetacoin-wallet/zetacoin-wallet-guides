Install Zetacoin Wallet on macOS 12 or later by downloading the disk image from the project's release page, dragging the app into Applications and allowing it once through Gatekeeper. It runs natively on Intel and Apple Silicon, needs about 2 GB of RAM, and stores its data in `~/Library/Application Support/zetacoin/`.

## The install in five steps

1. Download the macOS build, about 28 MB, from {{RELEASE}}.
2. Compare its SHA-256 value with the published checksum before opening it.
3. Open the disk image and drag Zetacoin Wallet into Applications.
4. Launch it, then approve the app in System Settings under Privacy and Security if macOS blocks it.
5. Let the wallet sync, encrypt it, and copy `wallet.dat` off the machine.

The gatekeeper step is the one that stops people. macOS blocks any application it cannot verify against a developer certificate, and this build is not signed with a paid one, so the first launch produces a refusal rather than a window.

The full walk-through, with the checks in order, is in [Where the Official Zetacoin Wallet Lives](https://github.com/zetacoin-wallet/zetacoin-wallet-guides/blob/main/where-the-official-installer-lives.md).

## Getting past Gatekeeper without disabling anything

The safe path uses the per-app override: open System Settings, go to Privacy and Security, scroll to the security section, and choose to open the app anyway. macOS then remembers that decision for that copy of the app.

The unsafe path is the one people find in forum posts: disabling Gatekeeper system-wide with a terminal command. That removes the check for every application on the machine, not just this one, and it is a permanent change for a temporary problem.

If the app still refuses to open after the override, the file is usually damaged rather than blocked, which means the download did not complete. Delete it and download again; a hash check would have caught this before the first launch.

## Where macOS keeps the wallet

The data directory is `~/Library/Application Support/zetacoin/`. Inside it, `wallet.dat` holds the keys, `zetacoin.conf` holds settings, and the chain data sits alongside them.

That path is hidden in Finder by default. Use Go to Folder in the Go menu, or press the equivalent shortcut, and paste the path. Backing up means copying `wallet.dat` from there to another location, not copying the whole folder onto the same disk.

macOS adds one more consideration: Time Machine. A Time Machine backup that includes the data directory is a real second copy, and restoring a machine from it can restore the wallet too  -  provided the backup was made after the file existed and the drive is not the one that failed.

For the background behind this step, [Zetacoin Wallet System Requirements](https://github.com/zetacoin-wallet/zetacoin-wallet-guides/blob/main/system-requirements-for-the-client.md) covers the same ground in more detail.

## What the first sync looks like on a Mac

The client opens to an empty overview and starts downloading the chain. On a fast connection a standard sync finishes in 30 minutes to two hours; the bootstrap archive shortens that to under 15 minutes by replacing the download with a snapshot of chain state.

The window will feel unresponsive during the first minutes. That is the client validating headers and opening its database, not a hang. Progress is visible in the sync indicator and in the peer count, and if both stay at zero for more than a few minutes the problem is connectivity rather than speed.

Leave the machine awake for the duration. A Mac that sleeps mid-sync pauses the download, and while it resumes on wake, a sync interrupted repeatedly takes far longer than one left alone.

## Apple Silicon and Intel

The build runs on both. On Apple Silicon it runs natively rather than through translation, so sync and staking behave the same as on Intel hardware. Memory use is modest: 2 GB of RAM is the stated minimum, and the client runs comfortably on an 8 GB machine.

The chain takes about 1 GB of disk. That is small next to a photo library and large enough to notice on a nearly full drive, so check free space before syncing rather than after. A drive that fills mid-sync leaves a partial database, which then looks like a corruption problem and costs more time than the check would have.

## Problems specific to macOS

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| "App is damaged and can't be opened" | incomplete download | delete, download again, verify the checksum |
| App blocked with no override offered | quarantine flag on the file | approve it in Privacy and Security, then relaunch |
| Wallet opens but never connects | firewall or VPN blocking the port | allow the app through, or disconnect the VPN and retry |
| Data directory not found | looking in the wrong Library | use Go to Folder with the full path |
| Balance missing after a restore | no rescan yet | rescan the chain from the console |

None of these are macOS-specific bugs; they are the same three underlying issues  -  an incomplete file, a blocked port, an unsynced wallet  -  wearing a Mac costume.

## Common questions

### Does Zetacoin Wallet run on Apple Silicon?

Yes, natively. The same disk image covers Intel and Apple Silicon Macs, and no translation layer is involved.

### Which macOS versions are supported?

macOS 12 and later. Older versions are not covered by the supported platforms.

### Why does macOS say the app is damaged?

Because the download did not complete, not because the app is malicious. Delete the file, download it again from the release page, and check the hash.

### Can I keep the wallet on an external drive?

Yes, by launching with a data directory on that drive, but the drive must stay connected while the wallet runs and its path must not change. For a wallet you rely on, the internal disk plus an off-machine backup is the simpler arrangement.
