Zetacoin Wallet is the official open-source desktop client for the ZET network. It holds your keys in `wallet.dat`, syncs the full chain on your own machine, sends and receives ZET, stakes mature coins when unlocked, and can mine or serve as a node. It runs on Windows, macOS and Linux and is actively maintained.

## What the client actually is

The client is a Qt desktop application that runs a full node in the same process. That single design decision explains most of its behaviour: it downloads and validates the chain itself rather than asking a server for balances, so the first launch is slow and everything afterwards is authoritative.

Running a full node costs disk and time and buys verification. When the wallet shows a balance, that balance is derived from blocks your machine checked against consensus rules. When it shows a transaction as confirmed, the confirmations are counted from your own chain, not from an API that could be wrong or lying.

The data directory holds the chain, the configuration and the wallet file. Everything the client knows lives in one folder, which is convenient for backups and dangerous for upgrades, because an old installation's folder is exactly where the new client will look first.

The full walk-through, with the checks in order, is in [What Is Zetacoin? The Scrypt Coin Behind the ZET Wallet](https://github.com/zetacoin-wallet/zetacoin-wallet-guides/blob/main/what-is-the-zet-coin.md).

## The window, in parts

| Area | What it shows | What it is for |
| --- | --- | --- |
| Overview | balance, recent transactions, staking state | the daily view |
| Send | address, amount, fee | broadcasting a payment |
| Receive | your addresses and labels | giving someone a `9...` address |
| Transactions | history including stake entries | confirming what happened and when |
| Staking | staking toggle and status | unlocking coins for block production |
| Console | RPC command line | inspection and repair |

The overview is where most people stay. It reports whether the wallet is synced, how many peers are connected, and whether staking is on. A grey staking icon almost always means one of three things: the wallet is locked, it is not fully synced, or the coins have not matured yet.

## First launch, step by step

1. Install the build for your platform from the project's release page and open the client.
2. Let it create the data directory and begin syncing. A standard sync takes 30 minutes to two hours; the bootstrap archive cuts that to under 15 minutes.
3. Create or confirm your receiving address and check that it begins with `9`.
4. Encrypt the wallet with a passphrase you will not lose, because there is no recovery mechanism.
5. Copy `wallet.dat` to storage outside the machine before you hold a meaningful balance.

Skipping step five is the most expensive shortcut in the whole process. The file is the wallet; without a copy, a failed disk means the coins are gone, and no seed phrase exists to rebuild them because this client never used one.

For the background behind this step, [Is the Zetacoin Wallet Safe to Use?](https://github.com/zetacoin-wallet/zetacoin-wallet-guides/blob/main/is-the-desktop-client-safe.md) covers the same ground in more detail.

## Sending, receiving and fees

Sending needs an address, an amount and a fee. The recommended fee setting is `paytxfee=0.001` in `zetacoin.conf`, and leaving it there produces transactions that confirm normally on a 30-second chain.

Receiving is a matter of handing over an address. Addresses begin with `9` on the current chain; a `Z...` address belongs to the retired chain and cannot receive current ZET. That single check prevents a class of support tickets that look like lost funds but are actually misdirected coins.

A transaction that appears stuck is usually a fee or connectivity problem rather than a chain problem. The client rebroadcasts, and a transaction that never reached a peer has to be re-sent. Waiting for confirmations on a 30-second chain is quick once the transaction reaches the mempool, so the useful diagnostic is whether it reached a peer at all.

## Staking from the client

Staking turns holdings into block production. Unlock the wallet for staking only, keep it running and synced, and coins that have matured for roughly eight hours become eligible for a flat 0.0625 ZET reward per PoS block.

There is no minimum balance. A small balance stakes rarely, which is a matter of probability rather than permission, and the reward appears in the transaction list as a stake entry. Staking and mining can run at the same time from the same installation, because they are separate paths to the same chain.

{{ARTICLE:how-to-stake-zetacoin-coins}} has the full setup, and {{ARTICLE:zetacoin-staking-not-working-fix}} covers the grey-icon cases.

## Where the client keeps your data

Windows uses `%AppData%/zetacoin/`, Linux `~/.zetacoin/`, and macOS `~/Library/Application Support/zetacoin/`. Inside that folder, `wallet.dat` holds the keys and `zetacoin.conf` holds settings such as the fee, the ports and any node addresses.

Because the folder is shared with earlier installations, an upgrade needs care: back up the old `wallet.dat`, move the old chain data aside, and let the current client build its own. Doing that in the other order risks the new client reading a retired chain and appearing broken.

{{ARTICLE:where-is-zetacoin-wallet-dat}} gives the exact paths per platform, and {{ARTICLE:move-zetacoin-wallet-new-computer}} covers migrating the folder intact.

## What it does not do

It does not store a seed phrase, so there is no twelve-word backup and no wallet-restore-from-words flow. It does not phone home for balances, so a firewall block on the network port shows up as zero peers rather than a wrong balance. It does not swap legacy coins, because that window closed.

Knowing those three limits answers a large share of the questions people bring to the client. A wallet that does not do a thing is not broken when it fails to do it; it is behaving as designed. {{ARTICLE:zetacoin-wallet-seed-phrase-explained}} covers the first limit in detail.

## Common questions

### Is Zetacoin Wallet a full node?

Yes. The client downloads and validates the chain itself, which is why the first sync takes time and why balances are verified locally rather than fetched from a server.

### Can I run it on two computers?

You can run two installations with separate data directories, but not two clients sharing one `wallet.dat` at the same time. Copy the file rather than pointing both machines at it.

### Does it need port forwarding?

No. Port forwarding on 17333 improves how many peers can reach you and helps the network, but the wallet syncs without it.

### Why does the wallet use so much disk?

Because it holds the full chain, about 1 GB of chain data, and the folder grows with the chain. The client needs roughly 2 GB of RAM to run comfortably.
