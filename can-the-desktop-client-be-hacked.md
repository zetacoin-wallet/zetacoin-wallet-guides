A Zetacoin wallet can be compromised through the machine it runs on or a fake installer, not through the chain. There is no central server holding balances, so the realistic attacks are malware reading an unencrypted `wallet.dat`, a stolen device, a copy of the passphrase, and software downloaded from an imitation site.

## What there is to attack

A self-custody wallet has no account to breach and no server that holds coins. What exists is a file on a machine, a passphrase in your head or a password manager, and an installer you ran at some point.

Every realistic attack targets one of those three. The chain itself is not the weak point, and neither is the cryptography in the wallet file.

| Attack | How it works | Defence |
| --- | --- | --- |
| Malware reading the file | runs as your user, copies `wallet.dat` | encryption, clean machine |
| Stolen device | takes the whole disk | encryption, off-machine backup |
| Fake installer | imitates the download page | checksum verification |
| Passphrase theft | phishing, reused password, screenshot | unique passphrase, stored apart |
| Address substitution | clipboard malware changes a paste | check first and last characters |

The full walk-through, with the checks in order, is in [Is the Zetacoin Wallet Safe to Use?](https://github.com/zetacoin-wallet/zetacoin-wallet-guides/blob/main/is-the-desktop-client-safe.md).

## The unencrypted file is the big one

An unencrypted `wallet.dat` gives whoever reads it the keys. They do not need your passphrase because there is none, and they do not need to interact with you at all.

Encryption changes that in one step. A stolen encrypted file is useless without the passphrase, which moves the attack from the file to the person holding the passphrase.

That is why encryption is the first recommendation on every page here, ahead of any discussion of antivirus or browsing habits.

## Fake installers and lookalike sites

An imitation download page with a working wallet-shaped installer is the most effective attack on this audience, because the victim does the work. The installer runs with their permissions and has access to everything the wallet does.

The defence is a hash comparison against the value the project publishes. A file that matches is the project's file; a file that does not is not, regardless of how convincing the page looked.

Never install from a link in a message, an advertisement or a mirror. Start at the release page.

For the background behind this step, [Does Zetacoin Use a Seed Phrase?](https://github.com/zetacoin-wallet/zetacoin-wallet-guides/blob/main/is-there-a-seed-phrase.md) covers the same ground in more detail.

## Social attacks

The most common approach is not technical. A message claiming to be support, offering to recover funds, or asking you to "verify" a wallet asks for the file or the passphrase, and no legitimate process ever does.

The same applies to airdrop claims and migration announcements. The chain has no claim mechanism, and there is no migration open. A page that asks you to connect a wallet or sign a message to receive coins is harvesting access.

## What a compromised machine looks like

The warning signs are ordinary: a wallet file whose modification time changed without a transaction, a balance that moved without you, or a passphrase that suddenly does not work.

If any of those appear, treat the machine as untrusted. Move remaining funds from a clean machine using a fresh installation, create a new wallet rather than reusing the old one, and stop using the affected device for anything involving keys.

## Reducing the surface

Run the wallet on a machine you keep clean, encrypt the file, keep the passphrase elsewhere, back up off the machine, and install only from the release page. Those five practices cover the realistic attacks.

Beyond that, treat every unsolicited message about your wallet as hostile, and every request for a file, phrase or signature as theft.

## Common questions

### Can someone steal coins from the blockchain?

No. There is no administrator and no central balance to seize; coins move only with keys.

### Is an encrypted wallet safe if my laptop is stolen?

The file is unreadable without the passphrase, so the theft does not by itself give access to the coins.

### Can a wallet be hacked remotely?

Only through software running on the machine that can reach the file, or through a fake installer you ran.

### What should I do if I think I was compromised?

Move funds from a clean machine to a new wallet, then investigate the old one offline.

## The short version

The file is the target, the passphrase is the lock, and the download page is the door. Encrypt, back up, verify hashes, and ignore everyone who asks.

## Why the file is the whole target

A self-custody wallet concentrates value in one artefact. There is no account to phish, no session to hijack and no server to breach; there is a file, and whoever obtains it obtains the coins unless it is encrypted.

That concentration is the price of self-custody, and it is why the defences are all local. Encryption, a clean machine, an off-machine backup and a disciplined download are sufficient for the realistic attacks, and none of them depends on the project.

## What to do after a compromise

Speed matters more than diagnosis. Move remaining funds from a clean machine using a fresh installation, create a new wallet rather than reusing the compromised one, and only then investigate.

Sending the old file to anyone for inspection is the second stage of the same attack. The file is evidence, not a support attachment, and no legitimate process asks for it.

{{ARTICLE:how-to-backup-zetacoin-wallet}} and {{ARTICLE:where-to-download-official-zetacoin-wallet}} are the two practices that close most of this surface.

## The habits that matter more than tools

Encryption, a backup, a verified download and a clean machine cover the realistic attacks, and none of them is expensive or technical. What they require is consistency: the backup made after the last transaction, the checksum checked on every update, the message ignored every time it arrives.

Consistency is where people fail, and the failure is usually a single skipped step at the moment it mattered. A backup that is one transaction stale is a backup that loses that transaction; a download that skipped the hash is a download that could be anything.

{{ARTICLE:how-to-backup-zetacoin-wallet}} and {{ARTICLE:zetacoin-wallet-encryption-passphrase}} are the two pages that carry those habits in detail.

The single most useful habit is the one performed before anything else: verify the file came from the release page.
