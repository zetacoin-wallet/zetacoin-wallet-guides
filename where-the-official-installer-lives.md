The official Zetacoin Wallet is published on the project's GitHub releases page, with checksums alongside the builds. Install only from there. Domains with similar names host unrelated pages, and a wallet installer downloaded from one of them is the single fastest way to lose coins.

## The only source that counts

| What you need | Where it comes from |
| --- | --- |
| Windows installer | the project's release page |
| macOS disk image | the project's release page |
| Linux archive | the project's release page |
| File hashes | the checksums published with the release |
| Release notes | the same release entry |
| Source code | the project's repository |

Everything else is a copy at best. A mirror, a download site, a forum attachment and a search-advertised page are all copies, and a copy can differ from the original in ways you cannot see.

The reason to be strict is not paranoia about the project. It is that the download step is the one point where a mistake is unrecoverable, because the file runs with your permissions before you have any chance to check it. It is that a wallet installer has full access to your machine at the moment you run it, and it has an obvious motive to look like the real one.

The full walk-through, with the checks in order, is in [Download the Zetacoin Wallet for Windows](https://github.com/zetacoin-wallet/zetacoin-wallet-guides/blob/main/download-for-windows-64-bit.md).

## How a fake download actually works

The pattern is consistent. A domain close to the real name serves a page that copies the layout, quotes the current version number and offers a button. The file it serves may even open a wallet-shaped window, which is why the victim does not notice for weeks.

Behind the window, the installer copies the wallet file or the passphrase somewhere else. Nothing appears wrong until a balance moves, and by then the coins are on another chain entirely.

Two details make this hard to spot: the page is often indexed and can appear above the real one, and the file sometimes passes a superficial virus scan because it is not malware in the classic sense  -  it is a wallet with an extra function.

The defence is not vigilance in the abstract. It is a hash comparison against the value the project published, done every time, on every machine.

## The hash check, in one minute

Download the file, compute its SHA-256 value, and compare it with the published value. If they match, the file is the one the project built. If they differ, delete it without opening it.

On Windows, the certificate warning will appear regardless, because the binaries are not signed with a commercial certificate. That warning is about provenance and reputation, and the hash is the answer to it. A file that matches the hash is the project's file, whatever Windows says about the publisher.

On macOS the equivalent moment is Gatekeeper refusing the first launch. Approve the app in Privacy and Security after the hash matches; do not disable Gatekeeper for the whole machine to get past one dialog.

For the background behind this step, [Install the Zetacoin Wallet on macOS](https://github.com/zetacoin-wallet/zetacoin-wallet-guides/blob/main/install-on-macos-walkthrough.md) covers the same ground in more detail.

## What the project does and does not control

The project publishes the client, the checksums and the release notes. It does not control search results, aggregator pages, wallet comparison sites or the domains that imitate the project's name.

That limit matters when something goes wrong. If you installed from an imitation, no support channel can undo it, because the software you ran was never the project's. Recovery depends on moving remaining funds to a clean machine with a genuine install  -  and on the attacker not having taken everything yet.

This is also why naming lookalikes in a guide is a bad idea: it gives them the traffic and the link. The safer instruction is the positive one  -  go to the release page, check the hash, install from that file.

## Keeping an install trustworthy over time

A genuine install can be kept genuine. Update from the release page rather than from an in-app prompt or an emailed link. Verify the checksum on each update, because an update is a new binary with no reputation history.

Back up `wallet.dat` after each update so that a bad build cannot cost you the file. And keep the installation folder out of shared or synced directories that other software writes to.

## If you think you installed a copy

Treat the machine as compromised. Move any remaining balance to a wallet on a clean machine using a fresh installation from the release page, create a new wallet rather than reusing the old one, and change any passphrase you entered on the suspect machine.

Do not send the old wallet file to anyone offering to inspect or recover it. That offer is the second stage of the same attack, and it arrives by direct message within hours of a public post about a loss. The sequence is reliable enough to be predictable: first a public post, then a private message from an account with a support-shaped name.

## Common questions

### Is the website or GitHub the official download?

The release page is where the builds actually come from. Use it directly rather than a page that links to it, so that the file you get is the file the project published.

### Are the downloads signed?

The project describes its releases as audited and signed, and publishes checksums with each release. Verify the hash; that is the check you can perform yourself.

### Why does antivirus flag the installer?

Because the binaries are unsigned, heuristics treat them as unknown. That is not a virus report, but it is also not proof of safety  -  the hash is what resolves it.

### Can I download from a mirror if the main link is slow?

A mirror serves a copy you cannot verify against the project's own build. Wait for the direct download instead; a slow download is a much smaller problem than an unverifiable installer.
