Updating means installing the current release from the project's release page over your existing data directory, and the safe order is backup first, install second, verify third. Copy `wallet.dat` off the machine, keep the old chain data separate, then let the new client build its own. Current releases are on the GitHub releases page.

## Why an update is the answer, not a workaround

Most wallet problems people search for are already fixed in the current release. Sync failures, connection issues, build problems on newer systems and passphrase handling have all moved on, and an installation from an earlier year is running code from before those changes.

That is why the recommended first step for odd behaviour is to update rather than to hunt for a setting: the release notes describe what changed, and the change is usually the fix. The client's development is ongoing, the fixes ship in releases, and staying on an older build means running the version where the problem existed.

| Situation | What to do |
| --- | --- |
| Wallet misbehaves in a way you cannot explain | update, then retest |
| Wallet is years old and never synced fully | back up, update, resync with bootstrap |
| Wallet works fine | still update, then keep the file backed up |
| Node runs unattended | update deliberately, with a backup and a restart plan |

The full walk-through, with the checks in order, is in [Download the Zetacoin Wallet for Windows](https://github.com/zetacoin-wallet/zetacoin-wallet-guides/blob/main/download-for-windows-64-bit.md).

## The safe update, in order

1. Close the wallet so it releases the database.
2. Copy `wallet.dat` from the data directory to storage outside the machine.
3. If the installation predates the 2021 rebuild, move the old chain folder aside rather than deleting it.
4. Download the current release from {{RELEASE}} and verify its checksum.
5. Install or extract it, then launch it and let it sync.
6. Confirm your addresses are present and begin with `9`.
7. Only then delete the old folder, if you are confident the new client is healthy.

Steps two and three are the ones people skip, and they are the only ones that matter if something goes wrong. Everything else is reinstallable.

## The data-directory collision

The current client uses the same data directory as earlier versions, including the legacy wallet. That is convenient for upgrades and dangerous for one specific case: an old installation whose folder holds a retired chain and an old wallet file.

If the new client opens that folder, it may follow the retired chain, show an old balance and appear broken. The fix is not to fight it but to separate the two: rename the old folder, let the current client create a fresh one, and restore your `wallet.dat` into it deliberately.

Renaming is reversible. Overwriting is not. That asymmetry is the whole reason this article exists in this order, and it is also why the backup happens before the install rather than after it.

For the background behind this step, [How to Back Up the Zetacoin Wallet](https://github.com/zetacoin-wallet/zetacoin-wallet-guides/blob/main/how-to-back-up-the-dat-file.md) covers the same ground in more detail.

## What to verify after the update

Check four things before you transact. The block height should climb, the peer count should be above zero, the balance should match what you expect, and the addresses should begin with `9`.

If the balance is missing, the likely cause is a wallet file that was restored without a rescan. The client needs to walk the chain to find the transactions belonging to those keys, which is normal after a restore and takes time proportional to chain size.

If the height does not climb, the update is not the problem; connectivity is. {{ARTICLE:zetacoin-wallet-not-syncing-fix}} covers the sequence, and {{ARTICLE:fix-no-block-source-zetacoin-wallet}} covers the case where the client cannot find peers at all.

## Updating on each platform

Windows and macOS take an installer or a disk image; Linux takes a fresh archive that replaces the old folder. In every case the data directory stays where it is, so the wallet file survives the update as long as you did not delete it.

The one platform-specific caution is macOS, where a blocked app after an update looks like a failed install. It is the same Gatekeeper behaviour as the first install, resolved the same way, and it says nothing about the update itself.

{{ARTICLE:download-zetacoin-wallet-for-windows}} and {{ARTICLE:install-zetacoin-wallet-on-macos}} give the platform steps.

## What an update will not fix

An update cannot recover a forgotten passphrase, rebuild a deleted wallet file, convert legacy coins or repair a disk that lost the file. Those are data problems, not software problems, and no release changes the underlying facts: encryption has no recovery mechanism, the swap window closed, and the file is the wallet.

It also will not help a wallet that is failing because the machine is out of disk, out of RAM or blocking the port. Those are environmental, and updating on a machine that cannot run the client just produces the same failure with a newer version number.

How the client handles resources is a separate question from what the release contains, and so is where the wallet file lives  -  {{ARTICLE:where-is-zetacoin-wallet-dat}} answers the second.

## Common questions

### Will updating delete my coins?

No. Coins live in `wallet.dat`, and an update replaces the software, not the data directory. Back the file up anyway, because the one case where an update goes wrong is the case where the backup saves you.

### Do I need to resync after updating?

Usually not; the client reads the existing chain data. If the old data came from a different chain, or is corrupt, it will need to sync again from the current chain.

### Can I downgrade if the new version misbehaves?

Yes, by reinstalling the older build, but it is rarely the right move: the older build is where the problem was. Report the issue instead, and keep your backup intact.

### How do I know I have the current release?

Compare the version in the client's about window with the newest entry on the release page. If they differ, install the newer one.

## The short version

Back up `wallet.dat`, install the current release from {{RELEASE}}, verify the sync and the `9` prefix, then delete the old folder. That is the whole procedure, and it resolves more problems than any single setting.
