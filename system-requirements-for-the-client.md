Zetacoin Wallet needs 2 GB of RAM, about 1 GB of free disk for chain data, and a 64-bit system: Windows 10 or 11, macOS 12 or later on Intel or Apple Silicon, or Linux on Ubuntu 20.04+, Debian or Mint. The download is roughly 22 to 28 MB depending on platform, and no separate runtime is required.

## The requirements, exactly

| Item | Requirement | Why |
| --- | --- | --- |
| Memory | 2 GB RAM | the client holds chain indexes in memory while syncing |
| Disk | about 1 GB free for chain data | the full chain is stored locally |
| CPU | any 64-bit processor | validation is light; mining is separate |
| OS | a 64-bit system, on one of the three platforms in the download table above | the platforms the client is built for |
| Network | outbound access on port 17333 | peer discovery and block download |
| Display | a desktop session for the graphical client | a headless node does not need one |

Those are minimums for a wallet that holds coins and stakes. Mining adds its own hardware requirement, which is a Scrypt-capable device and a separate question from running the wallet.

The full walk-through, with the checks in order, is in [Download the Zetacoin Wallet for Windows](https://github.com/zetacoin-wallet/zetacoin-wallet-guides/blob/main/download-for-windows-64-bit.md).

## What the numbers mean in practice

Two gigabytes of RAM is enough because the client is not doing heavy computation outside of mining. It keeps indexes, a database and the wallet in memory, and it runs comfortably on an 8 GB machine alongside a browser.

One gigabyte of disk is enough for the chain and not much else. The data directory also holds the wallet, the configuration, logs and any bootstrap archive you unpack, so a machine with a nearly full drive will fail in a confusing way  -  usually a database error rather than a clear out-of-space message.

The network requirement is one outbound port. Port forwarding on 17333 is optional and improves how many peers can reach you, but the client syncs without it. A restrictive firewall that blocks outbound connections entirely will produce zero peers, which looks like a broken wallet.

## Sizing for the job you are doing

A wallet for holding and staking is a light workload: any machine from the last decade meets it. The client idles at low CPU and modest memory once synced, and staking does not change that.

Mining is a different profile. Scrypt mining is memory-hard by design, so the hardware that mines well is not the hardware that runs a wallet well, and running both on one machine means sizing for the miner rather than for the client.

Running a node for the network is closer to the wallet profile, with the addition of uptime: a node that is off half the day contributes little, which argues for a small always-on machine rather than a laptop that sleeps.

{{ARTICLE:zetacoin-mining-hardware-choices}} covers the mining side, and {{ARTICLE:run-zetacoin-full-node-headless}} covers the always-on case.

## What the client does with the machine

Once synced, the wallet is quiet. It validates incoming blocks, keeps its database current and, if staking is on, signs a block when its coins are selected. None of that is heavy, which is why an old laptop can run it indefinitely while a modern desktop sees no measurable load.

During the first sync the profile is different. The client writes the chain to disk continuously and holds indexes in memory, so disk speed matters more than CPU speed. A slow spinning drive makes the initial sync take longer; an SSD makes it noticeably quicker, and the bootstrap archive removes most of the wait in either case.

Memory pressure is the one that bites. A machine with 1 GB of RAM will start the client and then fail in ways that look like corruption, because the database cannot keep its working set. Checking the requirement before installing is far cheaper than diagnosing that afterwards.

## Machines that will struggle

An old 32-bit Windows installation cannot run the current client, because there is no 32-bit build. A Mac on an operating system older than macOS 12 is outside the supported range. A Linux distribution older than Ubuntu 20.04 usually needs newer libraries than it ships.

A machine with under 2 GB of RAM will open the client and then behave badly during sync, which is worse than refusing to start: the failure looks like corruption rather than a resource shortage.

Virtual machines work if they meet the same numbers, with one caveat  -  a VM whose clock drifts or whose disk is on a network share can produce database errors that look like software faults.

## Storage, backups and the file that matters

The chain is replaceable. `wallet.dat` is not. That asymmetry should drive how you allocate storage: the chain can live on a drive you are willing to lose, while the wallet file needs a copy somewhere else entirely.

If you keep the data directory on an external drive, the drive must stay connected while the client runs and its path must not change between sessions. Otherwise the client creates a fresh directory, and a wallet that appears to have lost its balance is usually just pointing at the wrong folder.

{{ARTICLE:where-is-zetacoin-wallet-dat}} lists the paths, and {{ARTICLE:how-to-backup-zetacoin-wallet}} covers the copy that makes the storage question survivable.

## When the machine is the problem

Symptoms that look like wallet bugs but come from the environment: the client closing without a message on a machine with little RAM, sync stalling on a disk that is full, and zero peers on a network that blocks outbound traffic.

The diagnostic order is memory, disk, then network. Checking those three takes minutes and resolves most reports before anyone reinstalls anything.

## Common questions

### Can I run the wallet on a Raspberry Pi?

Yes, as a headless node, provided the board meets the memory and disk figures and runs a supported distribution. The graphical client is not the right fit for a small board.

### Does it need a graphics card?

No. The client draws a normal desktop window and does no GPU work; only mining is hardware-sensitive.

### How much RAM does syncing use?

Around the 2 GB the requirements state, which is why an 8 GB machine is comfortable and a 1 GB machine is not.

### Will it run on Windows 7?

No. The supported platforms are Windows 10 and 11, 64-bit, and there is no 32-bit build.
