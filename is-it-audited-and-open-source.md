Zetacoin Wallet is open source: the code, releases and issue history are public. The project describes its releases as audited and signed, and a dedicated audit repository is being prepared by the dev team. The site and the repository disagree on the licence, so this page describes the wallet as open source without naming one until the owner confirms it.

## What open source means here

The client's source is published in the project's repository, alongside release notes and an issue tracker. That means the claim is checkable rather than promotional: anyone can read the code, build it, or compare a release against the source.

For a wallet, that matters more than for most software. The code handles keys, so the ability to inspect what it does with them is the difference between trust and faith.

The full walk-through, with the checks in order, is in [Who Maintains Zetacoin Now](https://github.com/zetacoin-wallet/zetacoin-wallet-guides/blob/main/who-maintains-the-project-now.md).

## The audit wording

The project describes its releases as audited and signed. That is the owner's own wording, and this pack uses it as given: no auditor name, report date or certificate is invented here, and none is implied.

The dev team is preparing a dedicated audit repository, which is where the evidence will live once it exists. Until then, the honest statement is the one the project makes, without embellishment.

## Signed releases and checksums

Each release publishes checksums, which is the part a user can verify directly. Computing the hash of a downloaded file and comparing it with the published value tells you whether the file is the one the project built.

The binaries are not signed with a commercial certificate, so Windows and macOS warn on first launch. That warning is about publisher identity rather than about the code, which is why the checksum is the check that actually answers the question.

For the background behind this step, [Is the Zetacoin Wallet Safe to Use?](https://github.com/zetacoin-wallet/zetacoin-wallet-guides/blob/main/is-the-desktop-client-safe.md) covers the same ground in more detail.

## The licence question, recorded rather than guessed

The project's site states one licence and the repository's sidebar reports another. That is a real inconsistency, and this pack does not resolve it by picking the more convenient answer.

What can be stated without ambiguity is that the client is open source and the code is public. The specific licence matters for people who intend to fork or redistribute, and the fix is a correction on one side or the other rather than an article choosing.

## Why this matters to a downloader

For someone installing a wallet, the practical questions are narrower than the legal ones: is the software the project published, and does it ask for anything it should not?

The checksum answers the first. The second is answered by behaviour: a legitimate client never asks for a seed phrase, never sends your file anywhere, and never requires a web login to unlock a local wallet.

## What an audit can and cannot tell you

An audit reviews code for specific classes of defect at a point in time. It does not guarantee that later changes are safe, and it does not cover the machine the wallet runs on.

That is why the operative security practices are local: encrypt the wallet, back up the file, keep the machine clean and install only from the release page. Those reduce risk in ways no report can.

## What a reader can verify without taking anyone's word

Three things are directly checkable. The source code exists in a public repository. The releases are published with notes. The checksums are published alongside the binaries.

None of those require trusting a statement about quality. They establish that the software is inspectable and that a downloaded file can be compared against what the project published.

## Why the licence inconsistency is recorded rather than resolved

When two official surfaces disagree, choosing the more convenient answer is how a documentation pack stops being trustworthy. The site says one licence, the repository sidebar reports another, and the correction belongs to the project.

What the inconsistency does not change is the practical position: the code is public, and the wallet is free to use. For anyone intending to redistribute or fork, it is a question to settle with the maintainers before relying on either statement.

{{ARTICLE:who-maintains-zetacoin-now}} covers who to ask, and {{ARTICLE:is-zetacoin-wallet-safe-to-use}} covers what a reader should check before installing.

## What to check in a release before installing

Read the release notes, confirm the build matches your platform, and compare the file's hash with the published value. Those three steps establish that the file is current, appropriate and unmodified.

Then install it and check one behaviour: that the client creates a data directory and begins syncing. A wallet that asks for a seed phrase, or wants a web login to unlock a local balance, is not this client.

That behaviour check is worth more than any claim about quality, because it tests what the software does rather than what a page says about it.
